# M1へのDesktop Relay移植チェックリスト

**2026-10-31時点：M1は未設置・未検証。** M4からM1へのSSHポート照会はタイムアウトした。電源、ホスト名、ポート、ネットワーク、SSH設定のどれが理由かを推測しない。既存のM1上で動いているAIやRemote Desktop Commanderを停止しない。

## A. M1本体で先に読むだけの確認

M1自身でTerminalを開き、次を実行する（秘密値は出力しない）。

```bash
uname -m
sw_vers
node --version
pnpm --version
cloudflared --version
command -v git
test -d /Applications/Dia.app && echo "Dia installed" || echo "Dia not installed"
```

M4実験では、Relay用Node 24がある一方、通常Terminalの既定はNode 22・pnpm 12でした。M1では指定されたNode 24以上とpnpm 10が実際の実行PATHで使われることまで確認してください。

あるいはこのガイドをクローンしたM1で `bash scripts/check_prereqs.sh` を実行する。Node 24以上、pnpm 10、Cloudflareの権限と既存のListen/LaunchAgentを確認する。事前に既存環境のバックアップ方針を決める。

## B. M1専用のHTTPS Endpoint

- M4と**別の資格情報・接続URL・Tunnel・Relay設定ディレクトリ**を用意する。
- 名前付きTunnelは例として `mcp-m1.example.com` （各自管理するドメイン）を使用する。
- 上流のREADMEに従って、M1上でリポジトリ取得、依存関係インストール、トンネル作成とDNSルーティング、Relayインストールを行う。
- 既存のMac上に8788を使う他のサービスがいないか調べる。既存のLaunchAgentを上書きしない。
- 認証URL・トークンはM1の安全な場所だけに保持し、GitHubやメッセージ本文へ貼り付けない。

具体的なコマンドは[共通の導入手順](../README.md#1-上流本体の取得)および[公式上流README](https://github.com/HashemKhalifa/desktop-relay#install-with-cloudflare)に記載。

## C. ChatGPTで別コネクタとして登録

1. M4側の既存接続を削除しない。
2. M1専用のカスタムMCPアプリを `DesktopRelayM1` のような識別名で追加する。
3. 最初はM1の専用テストフォルダを**読み取り専用**で列挙する。
4. M1側のMac名と対象パスを再確認して「M4を誤操作していない」ことを検証。
5. 書込・ターミナル・Dia操作は別々に本人が許可し、許可したMCPツールの範囲で検証する。
6. 必要なら登録ツールのRefreshを行い、ChatGPTの新しい会話で確認する。

## D. 操作の受入条件

| テスト | 合格条件 |
| --- | --- |
| 認証 | 無効資格ではアクセス不可。発行したM1資格で認証できる |
| Mac識別 | M1とM4の結果を明確に区別できる |
| 読み取り | M1テストフォルダのファイルを実際に読める |
| 書き込み | 許可したテストファイルに限り書け、読み戻せる |
| Dia | M1にDiaが存在し、対象タブを操作できる場合だけ実証 |
| UI保持 | フォーム入力後・送信後のタブが視認可能な状態で残る |
| 安全 | 認証情報が公開履歴に混入しない。他AIやRDCが停止していない |
