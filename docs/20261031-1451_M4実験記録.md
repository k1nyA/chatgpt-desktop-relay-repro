# M4実機の「これ、できるんじゃない？」検証記録

## 発想と背景

Remote Desktop Commander（有料・月間利用枠あり）が利用上限に達した状況でも、**MacにあるDesktop Commander Local MCPを自分の中継サーバーへつなげば、通常ChatGPTからMac操作できるのでは？**という発想から始まった。

ここで使ったのは、MIT公開OSS [HashemKhalifa/desktop-relay](https://github.com/HashemKhalifa/desktop-relay)。Remote Desktop Commanderのサービス設定や利用枠を変更したわけではない。

## 実機で見たもの（2026-10-31、日本時間）

1. M4の隔離実験フォルダに `desktop-relay` の公開ソースが存在した。上流 `main` に接続し、HEADは `b8b64c8`、作業ツリーに変更なし。package.jsonはDesktop Relay 0.2.0、MIT。
2. Relay実行系は専用のNode 24.22.2を使用。通常Terminalの既定はNode 22.23.3・pnpm 12.14.0だったため、再現時は実際の実行PATHを指定する必要がある。
3. Relayのlive構成は専用設定フォルダ、独立の認証資格ストアとローカルMCP起動コマンドを持つ。中身の秘密URL、トークン、鍵は公開していない。設定・認証ファイルは所有者のみ読めるモードが確認された。
4. Macローカルで `127.0.0.1:8788` のListenを確認。別の実験ディレクトリには一時Cloudflare Tunnelを起動・停止するスクリプトの痕跡があった。**現在つながっているEndpointがその一時Tunnelだと断定しない**。
5. ChatGPT上のカスタムアプリ `DesktopRelayM4` を選び `get_config` が成功。macOS/arm64、Node 24.22.2、Desktop Commander 0.2.52、client version 0.2.0と確認できた。
6. 同アプリの `start_process` によりMacで `date` と `hostname` を実行、実機の出力を取得。続いて `osascript` からDiaのタブURL一覧を取得し、終了コード0で複数の実タブの存在を確認。
7. つまり**ChatGPT → 認証付き中継 → M4 Local MCP → macOS → Diaタブ読取**の経路を実証した。一般のフォーム入力・クリック・完了画面保持、iOS ChatGPT、M1の独立接続はまだ実証していない。

## Orca側で同時に発見したもの

Orcaには `dia-browser-ops` の別Git作業ツリーがあり、Dia専用MCPの候補実装（フォーム読取・入力・検証、タブを保持する設計）とテストが**未コミット**で存在した。別エージェントの作業を尊重し、その未追跡ファイルを勝手に編集・add・push・一般公開しなかった。汎用Desktop Relayの成功とは別トラックとする。

## 実験と一般化した手順の違い

- 実験では隔離されたパス、接続用の資格情報、Cloudflareの一時中継などを扱ったが、**再現のために秘密ファイルを複製する必要はない**。
- 実験時の認証URLや運用中のブラウザタブを公開すべきではない。
- 公開READMEの安定運用のセットアップは、上流が説明する**名前付きCloudflare Tunnel**を採用。実験でその完全なセットアップが検証されたと主張しない。
- 他人のMacで使えること、iPhoneで使えること、永久無料であることも保証しない。
